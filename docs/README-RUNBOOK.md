# Pagination, filtering and retries

List tools return every result by default: the server follows pagination until the last page, and a cap you set with `UNIFI_PAGINATE_MAX_PAGES` marks a partial result `"incomplete": true` with an `incompleteReason`. A size argument (`page_size`, `pageSize` or `limit`) asks for that many records, gathered across as many upstream pages as needed; a position alone (`page_token`, `offset` or `page`) returns that one upstream page with its continuation marker. Resume a sized cursor list by passing its returned `_continuation` string back as `page_token` (`cursor` for Carrier Fabric); the Network v2 page-number queries return an exact `page_size` window and resume with `_nextPage`. A malformed continuation is refused before any upstream request. Network list tools take a `filter` expression that the UniFi controller evaluates. Only a read via `GET` is retried (on HTTP 429); a write, including a `GET` of a state-changing route such as the Protect camera enable-control, is sent exactly once. Details: [docs/PAGINATION.md](PAGINATION.md) and [docs/RETRY.md](RETRY.md).
